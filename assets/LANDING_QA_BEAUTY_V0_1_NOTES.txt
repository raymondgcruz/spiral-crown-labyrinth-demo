Spiral Crown Labyrinth — Landing QA / UI / UX Repair v0.1

Focus:
- Mobile landing arrival/refresh speed
- Desktop landing composition dignity
- Preserve mobile landing aesthetics
- Keep public hardening boundary intact

QA findings before patch:
1. LabyrinthScreen was eagerly imported into App, increasing landing work before the user chose Labyrinth.
2. Landing warm-load prefetch began too early on mobile and competed with first paint.
3. Returning-user desktop layout forced Daily Return into a narrow right column beside a huge image panel.
4. Welcome used remote Unsplash imagery in the landing atmosphere, adding network contention and making the visual field depend on external image loads.
5. Google Fonts import lacked explicit display=swap.
6. Hardened public build placed all vendor + app core in a single large entry chunk.

Patch:
- Made LabyrinthScreen lazy again.
- Delayed landing prefetches, especially on mobile.
- Deferred heavy chunk warming until later idle time.
- Rebuilt returning-user desktop landing into a centered sanctuary hero.
- Preserved Daily Return flow and mobile aesthetic.
- Removed remote background image from returning-user first paint.
- Made SacredImage lazy/async by default with low fetch priority.
- Added font preconnect links and display=swap.
- Split public hardened build into anonymous app entry + anonymous vendor chunk.
- Updated version to Public Demo v1.0-alpha.11-qa-beauty.1.
